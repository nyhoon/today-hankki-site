## 현재 진단

- GEO 감사: 11/11 페이지 점검, 점수 65/100, `fair`. 기술 99, 인용성 86, 구조화 데이터 75, 콘텐츠 62, 플랫폼 52, 브랜드 18.

- 우선 개선: 공식 개발사/브랜드 정보를 각 주요 페이지에서 일관되게 연결, 가이드 허브를 구조화, 출처·작성 주체·확인일 보강, 실제 사용 가치를 설치 전에 체험하게 하기.
- GEO 감사가 받은 일부 외부 플랫폼 자료는 측정되지 않았음: 브라우저 렌더 일치, YouTube 스캔, Reddit. 이를 0점이나 실패로 해석하지 않음.

## Google 사이트맵 진단

Google Search Console은 과거 XML, RSS, TXT 3개 제출 항목을 모두 `가져올 수 없음`으로 표시했음. 현재는 XML 한 개만 남기고 다시 제출했지만, 제출 직후 화면은 이전 읽기 오류와 0개를 계속 보여줌. 따라서 재처리는 제출 완료 상태이며, Google이 새 요청을 처리해 성공으로 바꿨다고 말할 수는 없음.

공개 XML은 200 응답, XML 파싱 성공, canonical 경로 URL 14개를 포함하며 페이지들도 응답함. robots.txt는 차단하지 않고, 수동 조치와 보안 문제도 감지되지 않음. Search Console의 sitemap 상세에는 보다 구체적인 HTTP/XML 원인이 나오지 않았음. 따라서 현재는 공개 파일 오류로 확정할 증거가 없으며 Google의 가져오기/처리 지연 또는 낮은 크롤 수요 가능성을 열어둠. 이는 진단 화면과 Google 문서에서 도출한 추론이고 확정 원인은 아님.

Google은 `Couldn't fetch` 원인으로 robots 차단, 수동 조치, 잘못된 URL, 서버 일시 오류뿐 아니라 낮은 크롤 수요도 안내함. URL 검사 Live Test에서 sitemap URL 자체가 성공적으로 가져와지는지와 Sitemaps 보고서의 최신 요청을 며칠 후 다시 확인할 것. sitemap을 계속 삭제/재등록하는 대신 공개 응답과 보고서의 최신 상태를 분리해 기록함.

네이버 진단에 남은 `https://nyhoon.github.io/favicon.ico` 5xx 항목은 호스트 루트의 아이콘임. 현재 프로젝트 하위 사이트의 공식 PNG 아이콘 사용과는 별도이며, 이 사이트 저장소에서 수정할 수 있는 경로가 아님.

## Slotbound에서 확인된 것과 적용 가능한 부분

Slotbound은 “마케팅을 전혀 안 했는데 운 좋게 떴다”로만 설명하기 어렵다. 개발자는 Steam 공개 데모를 만들고 Reddit에 게시했으며, 소수의 인디 게임 유튜버에게 이메일로 연락했다고 직접 답함. 그는 슬롯머신+로그라이크 디펜스의 한 줄 콘셉트가 눈에 띄었고 플레이어가 늘자 Steam이 노출을 더 줬을 수 있다고 추정했음. 이는 개발자의 가설이지 알고리즘이 확인한 인과 분석은 아님.

언론이 인용한 Steam 수치는 데모 첫날 최고 동시 플레이어 447명, 출시 전 위시리스트 10만 건, 첫 주 20만 판매. 특히 판매 급증 전에도 약 11개월간 개발과 데모·피드백의 누적 기간이 있었음. 핵심은 유료 광고보다 `한 문장으로 설명되는 독특한 약속 → 직접 해볼 수 있는 데모 → 제3자의 자발적 영상/추천 → 실제 사용 반응이 만든 플랫폼 추가 노출`에 가까움. 수치의 일부는 개발자 공개치를 언론이 인용한 것이며, 다른 제품에 그대로 재현된다는 보장은 없음.

알뜰한끼에 적용할 행동:

1. 설치 전 체험: 절약 추정액을 입력으로 직접 계산하는 공개 계산기를 추가함. 입력값은 브라우저 안에서만 계산하고 전송·저장하지 않음.
2. 앱의 한 줄 약속을 한 가지로: “집에 있는 재료부터 보고, 먼저 쓸 것과 오늘 메뉴를 찾는다.” 영수증 등록, 레시피, 위젯, 절약을 광고물마다 나열하지 않고 사용자 상황 하나씩 연결함.
3. 실제 시연: 가짜 UI·AI 음식사진보다 실제 앱에서 `재료 3개 선택 → 요리 후보 → 다 쓴 기록`이 어떻게 이어지는지 짧게 촬영함.
4. 작은 외부 채널 접촉: 냉장고 정리/1인 가구/살림/요리 분야의 작은 크리에이터와 커뮤니티 운영자에게 기능 시연을 제공하고 솔직한 사용 의견을 요청함. 대량 댓글·팔로우 자동화나 협찬을 숨기는 방식은 사용하지 않음.
5. 반복 루프: 첫 사용 후 “다음 장보기 전에 목록 확인” 또는 위젯 설정 같은 다음 행동을 앱 안에서 이어주고, 실제로 재방문이 생기는지 코호트로 확인함.

## 무료 실행 우선순위

1. Search Console: 사이트맵 XML 하나만 유지하고, 재제출 뒤 최신 `제출` 및 `마지막으로 읽음` 상태를 날짜와 함께 기록. Live Test는 재제출의 대체물이 아님.
2. Search Advisor: 사이트맵/RSS가 제출되어 있는 상태를 유지하고, 호스트 단위 데이터와 알뜰한끼 URL의 `site:` 색인 상태를 혼동하지 않음.
3. 자사 사이트: 가이드 허브, FAQ, 공식 사업자 정보, 앱 다운로드 식별정보를 서로 연결하고 실제 내용과 JSON-LD를 일치시킴.
4. 외부 신뢰: Naver Blog 한 곳에 글만 쌓기보다 YouTube Shorts와 공식 소셜에서 실제 화면·문제를 보여주고, 웹 가이드와 앱 설치 링크로 연결함. 관련 커뮤니티는 먼저 질문에 답하고, 앱 소개는 관련 맥락에서만 함.
5. 성과: GSC 브랜드/일반 키워드 노출과 클릭, 앱 스토어 방문·설치, 가입→키친 생성→첫 재료 3개 등록→7일 재방문을 분리해 확인. 다운로드 총합만으로 유기적 유입을 판단하지 않음.

- 홈페이지 `https://nyhoon.github.io/today-hankki-site/`는 Search Console에서 `URL이 Google에 등록되어 있음`, `페이지 색인이 생성됨`으로 확인됨. 최소한 홈페이지는 검색 색인에 들어가 있으며, 브랜드 검색 결과가 약한 문제를 사이트맵 수집 실패와 동일시하지 않음.
